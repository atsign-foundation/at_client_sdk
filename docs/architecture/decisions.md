# Architecture decisions

A decision binds only when it has a row here; a plan, design doc or project decision record elsewhere in this repo is a proposal until then. A row is added by a PR that a code owner approves ([CODEOWNERS](../../.github/CODEOWNERS)), and names the existing mechanism that was not used, and why. The rules every decision answers to are in [invariants.md](invariants.md).

| D-33 | A key store may keep its keys on the atServer as a sealed `@keys` document, which it locks, reads, writes and reads back only through a document store the session gives it; it never opens or holds a connection, and never sends or receives keys unsealed | The key store seam (`AtKeysIo`: `AtServerAtKeysIo`, `EnrollmentDocumentStore`); A8 amended | A key store that keeps keys on the device: a browser keeps no key material at rest (wasm K-14), so the passkey's keys live on the atServer, sealed under a key derived from the passkey | [wasm/decisions.md D-31](../projects/wasm/decisions.md) | gkc, 2026-11-20 |
| D-34 | The browser seals a passkey's records with a WebCrypto AES-GCM-256 key it imports `extractable: false`, for encrypt and decrypt only, from the 32 bytes HKDF derives from the passkey's PRF output, and then zeroes those bytes; `at_auth` has no default sealer | The record sealer seam (`RecordSealer`, returned by `PasskeyKeyDeriver`: `WebCryptoRecordSealer`, `WebCryptoKeyDeriver`); no invariant touched | at_chops' `AesGcm256EncryptionAlgo` over the key bytes: the page would hold the seal key as readable bytes for the whole session, where an imported non-extractable key is a handle it cannot read back | [wasm/decisions.md D-29](../projects/wasm/decisions.md) | gkc, 2026-11-20 |
| D-35 | Text read from the wire may appear in an exception message or a log line only quoted, with its control and format characters escaped and its length clipped, as `quotedClaim` does; key material, sealed or not, and secrets never appear in one | Exception messages and log lines; K5 amended | Messages that name types, fields and positions only, as K5 said before: the messages that quote a peer's envelope claim or an atServer reply are how a fault in another party's data is found, and quoting and escaping keep that text from reading as the SDK's own words | None | gkc, 2026-11-20 |
| D-36 | Keys a client cannot use are refused before anything is sent, with one exception type: `AtKeysUnusableException`, whose `cause` (`absent`, `unreadable`, `noAuthenticationKeypair`, `anotherAtsign`, `noCredential`, `pendingEnrollment`) says why and whose `source` names where the keys were looked for. The released `AtNoCredentialException` and `AtEnrollmentPendingException` become its subclasses, keeping every released constructor and field, and `AtKeysPassphraseException`, an `AtDecryptionException`, is an unreadable keyfile's `error` when its passphrase is missing or does not open it | The keys source seam: `AtKeysIo.describeSource` and `WrittenAtKeysIo.checkWritable`, new members with default bodies (A19); `Atsign.open`, `Atsign.resumeEnrollment`, `createAtClient`, activation and `CLIBase` | `AtOpenRefusedException` with a connection state: the connection state describes only the network and the atServer. `ArgumentError` and `UnAuthenticatedException`, which `CLIBase` and `createAtClient` threw before: neither says the keys are at fault, nor where they were looked for | None | gkc, 2026-11-21 |
| D-37 | An AtKeys store's pending enrollment is cancelled, on the device that filed it, by `PendingEnrollment.cancel`, which removes its pending keys and sends nothing. `at_activate cancel` and the Cancel of `PkamDialog` and `ApkamActivationDialog` call it. Each says the request is still on the atServer, for the Atsign's manager to deny, or to revoke if it was approved meanwhile | at_client_cli's `AuthCliCommand` gains a value; K7 | `at_activate enroll --cancel`: `enroll` makes four options mandatory that a cancel has no use for. A withdrawal on the atServer: at_server p3.20.0 refuses every enroll operation except `request` on an unauthenticated connection | None | gkc, 2026-11-22 |

| D-39 | each bridge release also publishes `bridge-manifest.json`, with a `schemaVersion`, listing every exported method and every error code, generated from the Dart constants the bridge uses and identical for both compile targets, and the at_js build downloads it with the bundle, checks its sha256 against the pin in `bridge.ref` and fails when its hand-written types or code list differ from it | The bridge's JS surface (`lib/src/js/`, as in #2537, not yet on trunk), the bridge release, at_js's pinned bundle; A20 (the at_js side is the literal pin) | The hand-kept lists: the code tables in `docs/projects/wasm/js-api.md` and the code set in at_js's `error.ts` are written by hand and nothing compares either with the bundle, so a code or method can change in one place only | None | proposed |
| D-40 | a bridge session is opened through one `SessionOpener` interface, with `KeysSessionOpener` and `PasskeySessionOpener` (a sealed `SessionOptions` choosing between them) each returning an `OpenedSession` (the `AtClient` and its stop), and the session's `close()` awaits that opener's stop | Session opening (`portalSession`, `passkeyLogin`, `SessionTransportOptions`), client teardown; A17 unchanged, A13 | The two entry points as they are on trunk: `portalSession` returns an `AtClient` and `passkeyLogin` a `PasskeySession` with its own stop; as in #2537, not yet on trunk, `bridge.dart` builds the keys session itself with `SessionTransportOptions`, so a passkey session would be a second opening path in the bridge whose vault release nothing awaits; a wrapper over the two would leave both names, so they are renamed as a matching pair | None | proposed |
| D-41 | every exception the package declares lives in `lib/src/exceptions.dart` and extends `AtException`; the exceptions on trunk today are `PortalSessionOfflineException`, `UnsupportedKeyMaterialException`, `JsCollectionsError`, `SetupLockTimeoutException` and `IndexedDbException`, and the exports of `lib/at_client_web_web.dart` keep working | Exceptions raised to a caller from `lib/src/session/`, `lib/src/keys/` and `lib/src/collections/`; A22 | The present spread: `PortalSessionOfflineException` and `UnsupportedKeyMaterialException` in `portal_session.dart`, `JsCollectionsError` in `js_collections_adapter.dart`, `SetupLockTimeoutException` in `web_setup_lock.dart` and `IndexedDbException` in `indexeddb_store.dart`; two of the five do not extend `AtException`, so a caller catching `AtException` does not see them, and a layer cannot name another layer's error class without importing the layer | frozen contract titles, with #2537: `every exception the package declares is declared in lib/src/exceptions.dart`, `every exception the package declares is an AtException`, `the barrels export every exception they exported before` | proposed |
