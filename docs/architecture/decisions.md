# Architecture decisions

A decision binds only when it has a row here; a plan, design doc or project decision record elsewhere in this repo is a proposal until then. A row is added by a PR that a code owner approves ([CODEOWNERS](../../.github/CODEOWNERS)), and names the existing mechanism that was not used, and why. The rules every decision answers to are in [invariants.md](invariants.md).

| D-28 | `AtClient.getMeta` looks up a key's metadata only, through the same lookup path as `get`, and takes `GetRequestOptions`; `AtCollection.upsert` decides that an item is held with it | `AtClient` public API; A10 (routing), A13, A19, A22, A24, A25 | `get`: decrypts and rewrites the key's metadata. `keyExists`: scans with the key as an unescaped regex and turns an authorisation refusal into "absent". `executeVerb` on the two secondaries from `AtCollection`: a second routing path beside `useRemoteAtServer`. A new method or options type: a second way to do the job, and a new public type | [get_meta_metadata_only.feature](../../features/at_client/get_meta_metadata_only.feature) | gkc, 2026-11-17 |
| D-29 | Every write of the server-held `@keys` document holds the enrollment's lock, a `ServerMutex` immutable record with a short ttl, from before it reads the document until it puts; a writer that finds it held waits and re-reads, and a write that would drop stored material is still refused | The server-held key store (`AtServerAtKeysIo`, `EnrollmentDocumentStore.tryLock`); K4 | None: it reuses `ServerMutex`, as `_nskeylock` and `_rootlock` do. | D-30 | The client closes no key store: `PasskeySession` owns the passkey's vault and its key store and closes the store and then the vault once the client has stopped, or after 10 seconds plus the longest one write may wait for the enrollment's lock (`AtServerAtKeysIo.lockWaitBound`, 75 seconds by default) if that stop or a queued `@keys` write is still running, and `ClosableAtKeysIo` is removed | Client teardown (`AtClient.stop()`), the key store seam (`AtKeysIo`); A17 unchanged | None: `stop()` and A17 stay as they are. The proposal, a key store whose lifetime `stop()` takes over through `ClosableAtKeysIo`, would have changed proven teardown | [wasm/decisions.md D-30](../projects/wasm/decisions.md) | gkc, 2026-11-17 |
| D-31 | Onboarding writes the `@keys` document and pointer before it deletes the CRAM secret, so an onboarding interrupted before its pointer is written is run again with the same CRAM secret, and the browser keeps no pending onboarding record, only the hints it writes once the CRAM secret is deleted | Passkey onboarding (`PasskeyCustody.onboard`), at_auth's deferred completion of an activation; K-14 stands | A sealed pending onboarding record in IndexedDB, the proposal: the activation already defers its completion, so the atServer holds the document before the CRAM secret is deleted and the device keeps nothing until then | [wasm/decisions.md D-32](../projects/wasm/decisions.md) | gkc, 2026-11-18 |
| D-32 | Once its pointer is written, an onboarding that an `Exception` stops throws `PasskeyOnboardingIncompleteException`, naming the Atsign with that exception as its `cause`, and a login with the passkey finishes it unless its enrollment has been revoked since; an `Error`, and any failure before the pointer is written, are thrown as they are | Passkey onboarding (`PasskeyCustody.onboard`, `onboardNewAtSign`) and the exports of `package:at_client/passkey.dart`; no invariant touched | The failing step's own exception, thrown as it is: it does not say whether the CRAM secret's delete took effect, so an app cannot tell whether to run the onboarding again or log in | [wasm/decisions.md D-33](../projects/wasm/decisions.md) | gkc, 2026-11-19 |
| D-33 | A key store may keep its keys on the atServer as a sealed `@keys` document, which it locks, reads, writes and reads back only through a document store the session gives it; it never opens or holds a connection, and never sends or receives keys unsealed | The key store seam (`AtKeysIo`: `AtServerAtKeysIo`, `EnrollmentDocumentStore`); A8 amended | A key store that keeps keys on the device: a browser keeps no key material at rest (wasm K-14), so the passkey's keys live on the atServer, sealed under a key derived from the passkey | [wasm/decisions.md D-31](../projects/wasm/decisions.md) | gkc, 2026-11-20 |
| D-34 | The browser seals a passkey's records with a WebCrypto AES-GCM-256 key it imports `extractable: false`, for encrypt and decrypt only, from the 32 bytes HKDF derives from the passkey's PRF output, and then zeroes those bytes; `at_auth` has no default sealer | The record sealer seam (`RecordSealer`, returned by `PasskeyKeyDeriver`: `WebCryptoRecordSealer`, `WebCryptoKeyDeriver`); no invariant touched | at_chops' `AesGcm256EncryptionAlgo` over the key bytes: the page would hold the seal key as readable bytes for the whole session, where an imported non-extractable key is a handle it cannot read back | [wasm/decisions.md D-29](../projects/wasm/decisions.md) | gkc, 2026-11-20 |
| D-35 | Text read from the wire may appear in an exception message or a log line only quoted, with its control and format characters escaped and its length clipped, as `quotedClaim` does; key material, sealed or not, and secrets never appear in one | Exception messages and log lines; K5 amended | Messages that name types, fields and positions only, as K5 said before: the messages that quote a peer's envelope claim or an atServer reply are how a fault in another party's data is found, and quoting and escaping keep that text from reading as the SDK's own words | None | gkc, 2026-11-20 |
| D-36 | Keys a client cannot use are refused before anything is sent, with one exception type: `AtKeysUnusableException`, whose `cause` (`absent`, `unreadable`, `noAuthenticationKeypair`, `anotherAtsign`, `noCredential`, `pendingEnrollment`) says why and whose `source` names where the keys were looked for. The released `AtNoCredentialException` and `AtEnrollmentPendingException` become its subclasses, keeping every released constructor and field, and `AtKeysPassphraseException`, an `AtDecryptionException`, is an unreadable keyfile's `error` when its passphrase is missing or does not open it | The keys source seam: `AtKeysIo.describeSource` and `WrittenAtKeysIo.checkWritable`, new members with default bodies (A19); `Atsign.open`, `Atsign.resumeEnrollment`, `createAtClient`, activation and `CLIBase` | `AtOpenRefusedException` with a connection state: the connection state describes only the network and the atServer. `ArgumentError` and `UnAuthenticatedException`, which `CLIBase` and `createAtClient` threw before: neither says the keys are at fault, nor where they were looked for | None | gkc, 2026-11-21 |
| D-37 | An AtKeys store's pending enrollment is cancelled, on the device that filed it, by `PendingEnrollment.cancel`, which removes its pending keys and sends nothing. `at_activate cancel` and the Cancel of `PkamDialog` and `ApkamActivationDialog` call it. Each says the request is still on the atServer, for the Atsign's manager to deny, or to revoke if it was approved meanwhile | at_client_cli's `AuthCliCommand` gains a value; K7 | `at_activate enroll --cancel`: `enroll` makes four options mandatory that a cancel has no use for. A `CLIBase` flag: a program that hands `CLIBase` its own parser throws `ArgumentError` on the unknown name (args 2.7.0). A withdrawal on the atServer: at_server p3.20.0 refuses every enroll operation except `request` on an unauthenticated connection | None | gkc, 2026-11-22 |
| D-38 | The compile target of the browser bridge is a build choice, so `tool/build.sh` takes `--target dart2js\|dart2wasm`, defaulting to `dart2js`, with `dart2wasm` strict, no silent fallback, and an unknown target exiting 1 | The bridge build (`packages/at_client_web/tool/build.sh`); no invariant touched | `tool/build.sh` as trunk has it: it takes no argument, always runs both compilers, warns and exits 0 when the dart2wasm build fails unless `WASM_REQUIRED=1`, and writes `at_client.js` rather than a named bridge bundle, so the target is implicit in whatever a script last ran | None | proposed |
| D-39 | each bridge release also publishes `bridge-manifest.json`, with a `schemaVersion`, listing every exported method and every error code, generated from the Dart constants the bridge uses and identical for both compile targets, and the at_js build downloads it with the bundle, checks its sha256 against the pin in `bridge.ref` and fails when its hand-written types or code list differ from it | The bridge's JS surface (`lib/src/js/`, as in #2537, not yet on trunk), the bridge release, at_js's pinned bundle; A20 (the at_js side is the literal pin) | The hand-kept lists: the code tables in `docs/projects/wasm/js-api.md` and the code set in at_js's `error.ts` are written by hand and nothing compares either with the bundle, so a code or method can change in one place only | None | proposed |
| D-40 | a bridge session is opened through one private function in the bridge that opens either kind of session (keys or passkey) and records its stop, and the session's `close()` awaits that stop; `portalSession`, `passkeyLogin`, `onboardNewAtSign` and `PasskeySession` keep their names and shapes. A second `close()` returns the same future and throws no new error; a `close()` called while the session is still opening waits for the open to settle, then stops what was opened; the longest wait is D-30's: the passkey vault closes once the client has stopped, or after 10 seconds plus `AtServerAtKeysIo.lockWaitBound` (75 seconds by default) from when the client's stop begins, and `close()` also awaits the client's own `stop()`; D-40 adds no bound of its own | Session opening (`portalSession`, `passkeyLogin`, `SessionTransportOptions`), client teardown; A17 unchanged, A13 | A public `SessionOpener` family returning an `OpenedSession`: `PasskeySession` already holds a client and its stop and closes the passkey's vault once the client has stopped (D-30), and `docs/sdk-shape.md` and `test/export_surface_test.dart` name `onboardNewAtSign` and `passkeyLogin`, so renaming them changes proven entry points for the bridge's sake. As in #2537, not yet on trunk, the bridge takes the open function through a test seam typedef (`OpenJsSession`) | None | proposed |
| D-41 | every exception the package declares lives in `lib/src/exceptions.dart` and extends `AtException`; the exceptions on trunk today are `PortalSessionOfflineException`, `UnsupportedKeyMaterialException`, `JsCollectionsError`, `SetupLockTimeoutException` and `IndexedDbException`, and the exports of `lib/at_client_web_web.dart` keep working | Exceptions raised to a caller from `lib/src/session/`, `lib/src/keys/` and `lib/src/collections/`; A22 | The present spread: `PortalSessionOfflineException` and `UnsupportedKeyMaterialException` in `portal_session.dart`, `JsCollectionsError` in `js_collections_adapter.dart`, `SetupLockTimeoutException` in `web_setup_lock.dart` and `IndexedDbException` in `indexeddb_store.dart`; two of the five do not extend `AtException`, so a caller catching `AtException` does not see them, and a layer cannot name another layer's error class without importing the layer | frozen contract titles, with #2537: `every exception the package declares is declared in lib/src/exceptions.dart`, `every exception the package declares is an AtException`, `the barrels export every exception they exported before` | proposed |

Where a "today" cell names `lib/src/js/`, `bridge.dart` or a symbol defined in one of them, it describes the bridge in #2537, which is not on trunk yet.
