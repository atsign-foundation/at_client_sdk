## Unreleased

- Release workflow `at_client_web_bridge_release.yaml`: a release is started by hand (`workflow_dispatch` from trunk). It builds `at_client_web.js` from `dart-workspace.lock` and attaches it with a sha256 file and a build provenance attestation to a prerelease tagged `at_client_web-bridge-<sha12>`. The workflow serializes runs, sets job timeouts, and checks both remote git tags and existing releases before building; PR CI checks `dart-workspace.lock` sync and builds `at_client_web_entry`.
- Browser bridge (`web/at_client_web_entry.dart`, built by `tool/build.sh` as `build/at_client_web.js`): `create` opens a keys-file session and returns `@JSExport` session and collection objects. Rejections carry `{code, message}`, with `id`, `owner`, `kind` and `failures` for collection failures; item data crosses as objects with no prototype.
- Bridge argument and marshalling behaviour: bridge property reads inspect own properties only; non-plain objects (`Date`, `Map`, `Set`, `RegExp`, typed arrays, `ArrayBuffer`, `Error`) are rejected in `data`, `where` values, and option objects naming the parameter; `create` validates `atSign`, `namespace` (folded to lowercase), and `rootDomain` upfront without echoing received values; `subscribe`, `onStatus`, and `watch` return `{code, message}` on non-function callbacks; invalid `address.owner` rejects with `COLLECTION_INVALID_ARGUMENT` naming `owner`; `get` and `COLLECTION_ITEM_TOO_DEEP` rejections preserve `id` and `owner`; and `AtOpenRefusedException`, `PortalSessionOfflineException`, `AtEnrollmentException`, and external `ArgumentError` rejections emit fixed or parameter-only messages.
- Session lifecycle and messaging: `close()` shares one in-flight teardown across concurrent callers, cancels active collection watches, and ensures collection calls and `watch` reject/answer `closed` after `close()`; in-flight `notify()` interrupted by `close()` rejects `closed`; `collection()` starts `notificationService` listening when `eventSource` is `'notifs'` or `'both'` (default) and validates `name`; `notify` validates keys upfront (`sharedBy` matching the session, no `public`/`cached` flags, valid key/namespace/`sharedWith`) rejecting with `bad_key` without sending, and skips recording failed sends in the sent-id set; `subscribe` validates `regex` upfront, checks notification keys and canonical `sharedWith`/`sharedBy`, and removes completed subscriptions; `onStatus` isolates listener errors and mid-dispatch removals; `approve` and `deny` serialize concurrent decisions per enrollment id; `EnrollmentConveyanceException` maps to `enrollment_conveyance_failed`, and `AtNoCredentialException` / `InvalidAtSignException` map to `bad_key`.
- Collections adapter (`JsCollection` / `JsCollectionsAdapter`): serializes concurrent `update`, `share`, `remove`, and explicit-`id` `create` operations per `(id, owner)`; preserves `StoppedException` as `closed`; safely logs unreadable records whose `key.toString()` throws `InvalidAtKeyException`; and formats warning logs and error tokens onto a single bounded line.
- Notifications sent while the page is closed or reloading are never delivered.

## 0.1.0

- Initial pre-release (unpublished): `portalSession` opens an ordinary `at_client` in the browser on in-memory storage and caller-supplied `AtKeys`, returning only once PKAM has succeeded.
- Direct transport by default, chosen with `SessionTransportOptions`; a dev proxy only when `proxyHost` and `proxyPort` are both set, or a `proxy:<host>` root. A host is a bare name or a bracketed IPv6 literal such as `[::1]`; anything else throws an `ArgumentError` naming the field.
- `portalSession` throws an `ArgumentError` for a `prefs` whose root is not the transport's, including a default `AtClientPreference()` passed with a proxy transport.
