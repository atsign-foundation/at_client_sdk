## 0.1.0

- When the browser's IndexedDB fails, `passkeyLogin`, `discardPendingOnboarding` and, before it activates the atSign, `onboardNewAtSign` throw `IndexedDbException`, an exported `AtException` whose message names the browser's error (such as `QuotaExceededError`); a failed write of the device's passkey hints after activation is the `OnboardingIncompleteException`'s cause instead. A passkey database a newer build upgraded now opens instead of failing with a version error.
- A pending onboarding record is dropped automatically only when the atServer explicitly refuses PKAM for that record's enrollment (a bad signature always; a denied, revoked or unknown or expired enrollment when the reply names it). A network error, timeout, closed socket or setup-lock timeout keeps it. `onboardNewAtSign` with a new CRAM tries the record first and, on such a refusal, drops it and continues with the new CRAM; `passkeyLogin` drops it and logs in through the pointer. A refusal during an explicit resume is a `PasskeyLostException` with `PkamRefusedException` as its cause; `SetupLockTimeoutException` and `PrfUnavailableException` are not wrapped.
- `discardPendingOnboarding(atSign)` is the user's "Discard" choice for an unfinished onboarding: it takes the setup lock and deletes the pending record; a second call does nothing. When no @keys document was written, this destroys the only copy of the new keys and the atSign needs a fresh enrollment (OTP and approval). It is never called automatically.
- An update to the stored @keys document builds on a fresh read of it, so a second tab's update after another tab's write lands.
- The auth seed is zeroed as soon as PKAM succeeds (an unfinished pending onboarding keeps it until its session opens), and `stop()` zeroes what it can. The client's key store holds the APKAM key pair for the session (private half as bytes, zeroed when `stop()` closes the store; the authenticator's copy cannot be wiped), never writes the APKAM private key to the stored document, and a write running at `stop()` finishes whole.
- `onboardNewAtSign` and `passkeyLogin` document that a `PasskeyLostException` caused by a failed prompt may be a plain cancel, and that nothing is deleted, revoked or cleared after one. `docs/projects/wasm/browser-onboarding.md` has the app guidance ("Try again" and "Reset", each with an info box; never reset automatically).
- `WebPasskeyPort` implements `UnknownCredentialSignal` through `PublicKeyCredential.signalUnknownCredential` when the browser has it, and ignores a missing or failing call. A passkey left by a failed onboarding that the browser does not remove is documented in `docs/projects/wasm/browser-onboarding.md`.
- Initial pre-release (unpublished): `portalSession` opens an ordinary `at_client` in the browser on in-memory storage and caller-supplied `AtKeys`, returning only once PKAM has succeeded.
- Direct transport by default, chosen with `SessionTransportOptions`; a dev proxy only when `proxyHost` and `proxyPort` are both set, or a `proxy:<host>` root. A host is a bare name or a bracketed IPv6 literal such as `[::1]`; anything else throws an `ArgumentError` naming the field.
- `portalSession` throws an `ArgumentError` for a `prefs` whose root is not the transport's, including a default `AtClientPreference()` passed with a proxy transport.
- Passkey custody: `onboardNewAtSign` registers a passkey for a fresh atSign, activates it and returns its client once PKAM has succeeded; `passkeyLogin` (`atSign` required) reopens it with the passkey, on a device that remembers the atSign or through the public pointer; `prfSupported` reports whether the browser can evaluate passkey PRF, and onboarding throws `PrfUnavailableException` before any ceremony when it cannot.
- Taking the atSign's setup lock gives up after two minutes with `SetupLockTimeoutException`; the section running under the lock is not bounded.
- The WebCrypto key deriver zeroes the JS buffers it reads the PRF output and derived bytes through, in the JS heap itself, under both dart2js and dart2wasm.
- IndexedDB holds the atSign's hints (credential id and enrollment id) and, only while an onboarding is unfinished, one pending record: the minted keys sealed with the passkey-derived key, without the APKAM private key. Nothing else is stored, and no key is stored unsealed. A reload after activation resumes from that record, on `passkeyLogin` or a retried `onboardNewAtSign`, and removes it only after the client has opened, so a failed open keeps it and the retry needs no new passkey or CRAM; a server error or throttling during PKAM keeps the record and reaches the caller unchanged. The database is now version 3 (a third object store holds the pending records); an existing version 2 database upgrades in place. An aborted or blocked IndexedDB write or open fails with an error instead of hanging, an open store closes when a newer database version is requested and reopens on its next operation, and `putHint` writes the credential id and enrollment id in one transaction.
- The browser is asked to make storage persistent (`navigator.storage.persist()`) before onboarding activates the atSign, and again after a passkey is remembered; a refusal fails neither.
- Adds a dependency on `package:web`.
