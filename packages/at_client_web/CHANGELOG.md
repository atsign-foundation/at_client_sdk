## Unreleased

- `tool/build.sh` builds `dart2js` (default) or `dart2wasm` for one target and accepts an optional bridge entry (proposed decision D-38, pending review).
- The release workflow builds one target per dispatch, resolves the workspace's dependencies at dispatch time (no lock is committed), records the Dart SDK version and the resolved `pubspec.lock`'s sha256 in the release notes, and publishes its files under a target-specific tag with build provenance and an SLSA provenance file.
- `bridge-manifest.json` publishes the exported bridge surface and error codes, generated from the Dart constants.
- `PortalSessionOfflineException` and `UnsupportedKeyMaterialException` now extend `AtException` (D-41), so a caller catching `AtException` starts catching them; both keep their names.
- Browser bridge (`web/at_client_bridge_entry.dart`, built as `build/at_client_web.js` by the release build): `create` opens a keys-file session, or a passkey session when asked, and returns `@JSExport` session and collection objects. Rejections carry `{code, message}`, with `id`, `owner`, `kind` and `failures` for collection failures; item data crosses as objects with no prototype.
- Passkey sign-in: `create` with `passkey: true`, `rpId` and `rpName` opens a passkey session (`passkeyLogin`) and returns the same `@JSExport` session; it needs no `keys` document, and a missing or mistyped field rejects with `invalid_argument` naming the field.
- Bridge argument and marshalling behaviour: bridge property reads inspect own properties only; non-plain objects (`Date`, `Map`, `Set`, `RegExp`, typed arrays, `ArrayBuffer`, `Error`) are rejected in `data`, `where` values, and option objects naming the parameter; `create` validates `atSign`, `namespace` (folded to lowercase), and `rootDomain` upfront without echoing received values; `subscribe`, `onStatus`, and `watch` return `{code, message}` on non-function callbacks; an invalid `address.owner` rejects with `invalid_argument` naming `owner`, as does any other caller mistake (a missing or mistyped option, a non-function callback to a call that rejects); `get` and `COLLECTION_ITEM_TOO_DEEP` rejections preserve `id` and `owner`; and `AtOpenRefusedException`, `PortalSessionOfflineException`, `AtEnrollmentException`, and external `ArgumentError` rejections emit fixed or parameter-only messages.
- Session lifecycle and messaging: `close()` returns the same teardown future to every later call, concurrent or sequential, so a failed teardown stays failed and each later call returns the same error with nothing re-running; it cancels active collection watches, and ensures collection calls and `watch` reject/answer `closed` after `close()`; in-flight `notify()` interrupted by `close()` rejects `closed`; `collection()` starts `notificationService` listening when `eventSource` is `'notifs'` or `'both'` (default) and validates `name`; `notify` takes the key as atKey text (`@bob:note.wavi@alice`), parsed once in the session with `AtKey.fromString` and checked with `AtKeyValidators`, rejecting `public:`, `cached:`, a recipient not written with `@` and text the parsers refuse with `bad_key` without sending, and skips recording failed sends in the sent-id set; a failed notify can reject `notify_failed`, `offline` or `timeout`; `subscribe` validates `regex` upfront, checks notification keys and canonical `sharedWith`/`sharedBy`, and removes completed subscriptions; `onStatus` isolates listener errors and mid-dispatch removals; `approve` and `deny` reject a second concurrent decision on the same enrollment id with `enrollment_in_flight`, naming neither the atSign nor the id; `EnrollmentConveyanceException` maps to `enrollment_conveyance_failed`, and `AtNoCredentialException` / `InvalidAtSignException` map to `bad_key`.
- Collections adapter (`ItemCollection` / `JsCollectionsAdapter`, opened by `AtClientSession`): serializes concurrent `update`, `share`, `remove`, and explicit-`id` `create` operations per `(namespace, id, owner)`, across every handle the session opens; a call on a closed session throws `SessionClosedException`, and it and at_client's `StoppedException` both reject `closed` with the message `the session is closed`; safely logs unreadable records whose `key.toString()` throws `InvalidAtKeyException`; and formats warning logs and error tokens onto a single bounded line.
- Error messages: the bridge authors every message JS sees, from the exception's type and structured fields. `InvalidKeyException` carries a `KeyRefusal` and a page that is not a secure context is an `UnsupportedOperationException` with an `UnsupportedOperation`, worded with the text JS saw before; an `UnsupportedError` (the setup lock raises one without `navigator.locks`) maps by type alone and rejects with the fixed text `the operation is not supported here`, its own text never read. Neither passes its own text through; the only text taken from an exception is an item-id refusal that AtCollection words, cut to one line of at most 128 characters. A failed notify can reject `notify_failed`, `offline` or `timeout`. No existing code changed; `invalid_argument`, `notify_failed`, `timeout` and `enrollment_in_flight` are new in this release.
- `create` reports several bad inputs in the order js-api.md gives: type checks and key decoding (`atSign`, `namespace`, `rootDomain` and `keys`, in that order, `keys` last), then options validation, so a `keys` that is not JSON (`bad_key`) is reported before an unusable `rootDomain`, or an atSign that does not parse.
- Notifications sent while the page is closed or reloading are never delivered.

## 0.1.0

- `portalSession`'s refusal of keys a session cannot hold says "an in-memory AtKeys store".
- The passkey formats a browser login depends on (at_auth's HKDF labels and sealed record layout, and at_client's names for the records on the atServer) are promised from the first stable release: after it they change only with a compatibility path.
- Renamed `at_client_web` (it was `at_client_wasm`): apps import `package:at_client_web/at_client_web_web.dart`. A browser that ran an earlier build no longer finds the passkey hints it saved, and logs in as one that does not remember the Atsign; what the earlier build saved stays until the site's data is cleared.
- `at_client_web_web.dart` re-exports at_client's core API and in-memory storage completely, with `PasskeySession`, which `onboardNewAtSign` and `passkeyLogin` return, and the exceptions they throw or carry as a cause: `PasskeyLostException`, `PasskeyOnboardingIncompleteException`, `PublicKeyMismatchException`, `MissingAtKeysDocumentException`, `PkamRefusedException`, `AtServerAtKeysLockedException` and its supertype `AtServerAtKeysWriteException`, and at_auth's `PrfUnavailableException`, `PasskeyCeremonyException`, `PasskeyRecordAuthenticationException` and `UnsupportedPasskeyRecordException`. A browser app needs no other SDK import.
- `clearPrfMiss()` clears a recorded PRF miss, so in a browser that cannot report PRF support onboarding tries the passkey again rather than refusing for 30 days. A passkey that onboarding creates but cannot use (its second prompt cancelled, or no usable PRF output) is reported to the browser as unknown where the browser supports it.
- `passkeyLogin` finishes an onboarding that stopped after writing its pointer, while that onboarding's completion is due: it deletes the CRAM secret, then revokes every other approved enrollment, then publishes the document's key. It publishes over another key only when the onboarding recorded that its own delete of the CRAM secret answered, and otherwise refuses another key before it sends any delete, revoke or publish. Once the completion is done it revokes nothing: it publishes the document's key when none is published, and refuses another. Each revoke is logged as a warning. It fails if any of these fails (a revoke that leaves another approved enrollment throws `AtEnrollmentException`), and a login that succeeds with this browser's saved hints sends none of them. `onboardNewAtSign` stores a new record on the atServer, `completion-due.<enrollmentId>.a.__e@<atSign>`, from before it writes the @keys document until the completion's last step, and records in it when the CRAM secret is deleted; onboarding fails if a write of that record fails. `onboardNewAtSign` deletes the CRAM secret, then revokes every other approved enrollment of the Atsign, then publishes the encryption public key.
- When an exception stops `onboardNewAtSign` once the passkey's pointer is written, it throws `PasskeyOnboardingIncompleteException`, naming the Atsign; `passkeyLogin` then finishes the onboarding, unless its enrollment has been revoked since or `passkeyLogin` refuses another published encryption public key. A failure before that is thrown as it is, and `onboardNewAtSign` is run again with the same CRAM secret.
- An IndexedDB failure that stops `passkeyLogin` or `onboardNewAtSign` reaches the app as `IndexedDbException`, an exported `AtException` whose message names the browser's error when it gave one (such as `QuotaExceededError`). A failed write of the passkey hints does not fail `onboardNewAtSign` or `passkeyLogin`: a warning is logged, the session is returned, and the next `passkeyLogin` saves them. A remembered credential id or enrollment id that IndexedDB cannot read, or an enrollment id whose stored bytes are not UTF-8, counts as no hints. A passkey database a newer build upgraded now opens instead of failing with a version error.
- An update to the stored @keys document builds on a fresh read of it, so a second tab's update after another tab's write lands.
- The auth seed is zeroed as soon as the APKAM key pair is derived from it, before PKAM, and stopping the passkey session zeroes what it can. The client's key store holds the APKAM key pair for the session (private half as bytes, zeroed when the session closes the store; the authenticator's copy cannot be wiped), never writes the APKAM private key to the stored document, and a write running when the client stops finishes whole unless it is still running after 10 seconds plus the longest one write may wait for the enrollment's lock (75 seconds by default), when the session closes the store and the vault anyway.
- `passkeyLogin` documents that a `PasskeyLostException` caused by a failed prompt may be a plain cancel, and that nothing is deleted, revoked or cleared after one. `docs/projects/wasm/browser-onboarding.md` has the app guidance ("Try again" and "Reset", each with an info box; never reset automatically).
- `WebPasskeyPort` implements `UnknownCredentialSignal` through `PublicKeyCredential.signalUnknownCredential` when the browser has it, and ignores a missing or failing call. A passkey left by a failed onboarding that the browser does not remove is documented in `docs/projects/wasm/browser-onboarding.md`.
- Initial pre-release (unpublished): `portalSession` opens an ordinary `at_client` in the browser on in-memory storage and caller-supplied `AtKeys`, returning only once PKAM has succeeded.
- Direct transport by default, chosen with `SessionTransportOptions`; a dev proxy only when `proxyHost` and `proxyPort` are both set, or a `proxy:<host>` root. A host is a bare name or a bracketed IPv6 literal such as `[::1]`; anything else throws an `ArgumentError` naming the field.
- `portalSession` throws an `ArgumentError` for a `prefs` whose root is not the transport's, including a default `AtClientPreference()` passed with a proxy transport.
- Passkey custody: `onboardNewAtSign` registers a passkey for a fresh Atsign, activates it and returns its `PasskeySession` once PKAM has succeeded; stopping the session or its client closes the passkey vault; `passkeyLogin` (`atSign` required) reopens it with the passkey, on a device that remembers the Atsign or through the public pointer; `prfSupported` reports whether the browser can evaluate passkey PRF, and onboarding throws `PrfUnavailableException` before any ceremony when it cannot.
- Taking the atSign's setup lock gives up after two minutes with `SetupLockTimeoutException`; the section running under the lock is not bounded.
- The browser zeroes the plaintext and seal key buffers it hands to WebCrypto, under both dart2js and dart2wasm.
- Passkey keys are derived with at_chops' `HkdfSha256`, a new dependency. The seal key passes through Dart memory before it is imported as a non-extractable WebCrypto key; copies made inside `HkdfSha256` are left to the garbage collector.
- IndexedDB holds only the Atsign's hints (credential id and enrollment id), written at the end of an onboarding or a login, after any step that completes the activation and before its client opens; no key is stored. An aborted or blocked IndexedDB write or open fails with an error instead of hanging, an open store closes when a newer database version is requested and reopens on its next operation, and `putHint` writes the credential id and enrollment id in one transaction.
- The browser is asked to make storage persistent (`navigator.storage.persist()`) before onboarding activates the atSign, and again after a passkey is remembered; a refusal fails neither.
- Adds a dependency on `package:web`.
